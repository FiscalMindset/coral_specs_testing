⚠️ Documented Coral limitations found this run

#LimitationDetail
1field valuessites_list_sites_lists_items_getfields(site_id, list_id, listitem_id) returns only odata_type + id — column values (names, departments, ticket statuses) are not exposed. sites_list_sites_lists_listcolumns does return the schema (e.g. Employee Directory: Title [required], Color Tag [read-only], ComplianceAssetId), so structure is enumerable, cell content is not.
2no user/group listsGET /users and GET /groups list functions are absent from the Coral catalog (searched %listusers%, %listgroups%, users_user_%, groups_group_% — only nested/copilot surfaces exist). Users/groups are resolvable only by known UPN/ID, never enumerated. Ground truth 231 users / 44 groups is not reproducible through Coral alone.
3top caps differSharePoint listitems tolerated top=500 (Recent Commits needs 225); Teams messages rejects top>50 (HTTP 400). Both are Graph-side limits surfaced faithfully by Coral, not connector bugs.
4no UPN in messagesChannel message payloads carry only teamworkUserIdentity.id + displayName; resolving authors to mailboxes requires a separate per-user call.
